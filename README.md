## ローカル確認方法

このリポジトリをクローンしたあと、`index.html` をブラウザにドラッグ＆ドロップで開くと、ヒーロー・拠点・活動などは表示されます。

ただし、**TOPIC（お知らせ）と お知らせ一覧（news.html）は `news.json` を fetch で読み込むため、ローカルサーバー経由でないと表示されません**（ブラウザの file:// 制限）。本番環境（GitHub Pages）では問題なく動作します。

ローカルで TOPIC まで確認したい場合：

```bash
# Python が入っている環境で
cd <このフォルダ>
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

## お知らせの追加・編集（`news.json` の運用）

ホームの TOPIC セクションと `news.html`（お知らせ一覧）は、ともに **`news.json` 1ファイル** を読み込んで表示しています。**お知らせを追加・編集したいときは、`news.json` を編集してコミットするだけ** で、ホームと一覧の両方が自動で更新されます。

### お知らせを1件追加する手順（GitHub Web UI で）

1. GitHub上のリポジトリを開き、`news.json` をクリック
2. 右上の鉛筆アイコン（Edit this file）をクリック
3. `"items": [` の直後（先頭）に、以下のブロックを1つ追加（カンマ忘れに注意）：

```json
{
  "id": "2026-05-09-new-topic-id",
  "date": "2026-05-09",
  "displayDate": "2026/05/09",
  "category": "プロジェクト",
  "title": "ここに見出し（30〜40字目安）",
  "summary": "一覧ページに表示される説明文。1〜2文で要点を。",
  "image": "images/news/2026-05-09.jpg",
  "url": "projects.html"
},
```

4. 下の `Commit changes` ボタンを押して保存
5. 数十秒〜数分でサイトに自動反映

### 各項目の意味

| 項目 | 必須 | 説明 |
|---|---|---|
| `id` | 必須 | 重複しない一意のID。「日付＋スラッグ」がおすすめ。例：`2026-05-09-trail-update` |
| `date` | 必須 | ソート用。`YYYY-MM-DD` の形式で書く |
| `displayDate` | 必須 | 表示用の日付。`2026/05/09` のような自由フォーマット |
| `category` | 必須 | カテゴリ。下表のいずれかを推奨（自由入力も可） |
| `title` | 必須 | 見出し。30〜40字程度が読みやすい |
| `summary` | 任意 | 一覧ページに表示される説明。ホームの TOPIC では使われない |
| `image` | 必須 | サムネイル画像のパス。`images/news/xxx.jpg` のようにリポジトリ内の画像を指すか、外部URL |
| `url` | 必須 | カードクリック時のリンク先。詳細ページがあるなら指定、なければ関連する既存ページ（例：`projects.html`） |

### 推奨カテゴリ

| カテゴリ | バッジの色 | 用途 |
|---|---|---|
| `プロジェクト` | 緑 | 次郎笈再生・フードリボン等の進捗報告 |
| `イベント` | 黄緑 | クマ祭り出店・ミーティング参加など |
| `営業情報` | 茶 | 営業開始・休業・メニュー変更 |
| `広報誌` | 金 | 奥槍戸やま日和の発行 |
| `メディア` | オレンジ | 新聞・テレビ取材掲載 |
| `行政連携` | 青 | 行政との協議・採択 |
| `団体` | グレー | 設立記念・組合員追加など団体内部 |

`news.html` ではこれらのバッジが色分けで表示されます。新しいカテゴリを追加した場合は表示はされますが、色は灰色になります（必要なら CSS で色を追加してください）。

### 表示順とソート

`date` 項目（`YYYY-MM-DD` 形式）で**降順ソート**されます。配列内の並び順は実は気にしなくてOKですが、**先頭に追加する習慣**にしておくと、後で目視で「最近追加した」「古い」が分かりやすくなります。

### サムネイル画像について

- `images/news/` フォルダを作って、ここに画像を入れるのが推奨です（例：`images/news/2026-05-09.jpg`）
- 推奨サイズ：**横800px × 縦450px 程度**（16:9）／JPG・容量200KB以下
- 一時的にUnsplash等の外部URLを `image` に入れても表示されますが、本番では自前画像に置き換えてください
- 画像が用意できない場合：他のお知らせの画像URLを流用しても可

### お知らせを修正・削除する

`news.json` の該当ブロックをそのまま編集（修正）、またはブロックごと削除（削除）してコミット。

### よくあるミス

- **JSON文法エラー**：カンマの位置、ダブルクォートの閉じ忘れ。エディタが赤線で教えてくれる場合が多い
- **画像が表示されない**：`image` のパスが間違っている／画像をリポジトリにコミットし忘れ
- **`date` を `displayDate` 形式（`2026/05/09`）で書いてしまう**：ソートが崩れます。必ず `YYYY-MM-DD` で

## GitHub Pages へのデプロイ

このリポジトリはそのまま GitHub Pages として公開できます。

1. GitHub上のリポジトリ Settings → Pages に進む
2. Source：`Deploy from a branch`
3. Branch：`main` / Folder：`/ (root)` を選択
4. `Save` をクリック
5. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開

### 独自ドメインを使う場合

リポジトリのルートに `CNAME` ファイル（中身は `awasanga.com`）を追加し、Settings → Pages の Custom domain で設定してください。`.nojekyll` ファイルが既に置いてあるので、Jekyll処理はスキップされます。
